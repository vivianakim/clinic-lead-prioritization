# 제안서 에이전트

입력: Top 30 순위 (예: `1 2 3`). 지정이 없으면 `1 2 3`.
원칙: **숫자는 코드가, 문장은 내가.** 나는 facts에 있는 숫자만 쓰고, 새 숫자·사실·사례를 만들지 않는다.

## 진행 상황 표시

각 단계를 시작할 때와 끝낼 때 사용자에게 단계 번호와 함께 한 줄로 알린다. 예:

```
[1/4 숫자 뽑기] 1·2·3위 facts 저장 완료
[2/4 문장 쓰기] 1위 작성 중… → 3건 작성 완료
[3/4 자동 검사] 2위 실패(facts에 없는 숫자) → 2단계로 돌아가 수정 → 3건 통과
[4/4 조립·기록] 제안서 3건 저장, 47초
```

검사에 실패해 2단계로 돌아갈 때도 `[3/4 → 2/4]`처럼 어디로 돌아가는지 보이게 한다.

## 절차

1. **숫자 뽑기**
   ```
   .venv\Scripts\python -X utf8 src/03_proposal.py facts --ranks <순위들>
   ```
   → `outputs/proposals/work/facts/rankNN.json` (구 통계, 병원 특성, 추천 상품, ROI 가정값)

2. **문장 쓰기** — 각 facts 파일을 읽고 `outputs/proposals/work/text/rankNN.json`을 쓴다.
   ```json
   {
     "intro": "제안서 첫머리 2문장. 귀원의 상황과 제안 취지.",
     "product_reason": "추천 상품이 귀원에 맞는 이유 2~3문장. facts의 숫자를 근거로.",
     "questions": ["첫 미팅에서 원장에게 확인할 질문 1", "질문 2"]
   }
   ```
   문장 규칙:
   - 병원 이름(`_meta`의 병원명·익명명)을 쓰지 않고 **'귀원'**이라고 부른다.
   - 숫자는 facts에 있는 값(비율은 %로 바꿔도 됨)만 쓴다. 계산해서 새 숫자를 만들지 않는다.
   - 광고비·시술가·이익률·손익분기 숫자를 언급하면 바로 뒤에 **'(가정)'**을 붙인다.
   - 정중하고 간결한 존댓말. 과장 표현(최고, 무조건, 보장, 1등, 100%) 금지.
   - **환자 1명당 수수료·알선을 암시하는 표현 금지.** 광고는 정액 기준이다.
   - **우리가 병원을 고른 기준은 쓰지 않는다.** facts의 `_선정근거`(개원 연차, 전문의 수, 주변 안과 수, 구 비교값)는 영업 담당자용 내부 정보다. 병원에 보여 줄 이유가 없고 평가받는 느낌을 줄 수 있다. '개원', '중앙값', '반경', '전문의'라는 말도 쓰지 않는다 (검사가 막는다).
   - 문장은 병원에 도움이 되는 정보로 쓴다: 지역의 플랫폼 입점 현황, 귀원이 공개 중인 시술 가격(추천 상품을 고른 이유), 손익분기(가정).
   - 병원마다 facts가 다르니(지역 입점 현황, 공개 중인 시술) 문장도 그에 맞춰 다르게 쓴다.
   - 질문은 영업이 아니라 **병원의 상황을 듣는 질문**으로 쓴다 (신규 환자 경로, 늘리고 싶은 시술, 현재 마케팅 등).

3. **자동 검사**
   ```
   .venv\Scripts\python -X utf8 src/03_proposal.py check --ranks <순위들>
   ```
   실패하면 출력된 이유를 보고 해당 text 파일만 고친 뒤 다시 검사한다. 통과할 때까지 반복한다.
   (검사 항목: 키 형식·질문 2개, facts에 없는 숫자(`_선정근거` 숫자 포함), 병원명·익명명 노출, 금지 표현, 선정 기준 표현, '(가정)' 누락)

4. **조립·기록**
   ```
   .venv\Scripts\python -X utf8 src/03_proposal.py render --ranks <순위들>
   ```
   → 원본 `outputs/proposals/rankNN_<병원명>.md` (git 제외), 익명본 `outputs/public/proposals/`,
     생성 시간 `outputs/proposals/generation_log.csv` (facts 시작부터 완료까지 초)

5. **보고** — 순위별 익명명, 검사 통과 여부(재작성 횟수 포함), 생성 시간, 익명본 경로를 짧게 알린다.

## 하지 않는 것
- 실제 병원에 연락하거나 메일·메시지를 보내지 않는다.
- facts의 숫자나 ROI 가정값을 바꾸지 않는다. 가정값 변경은 `src/roi.py`에서 사람이 한다.
- 검사에 실패한 문장으로 제안서를 만들지 않는다 (render가 자동으로 거부한다).
